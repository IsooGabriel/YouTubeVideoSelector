### 1.3 マッチ規則

| 項目 | 規則 |
| :--- | :--- |
| 方式 | 部分一致 |
| 複数キーワード | 空白（半角・全角）区切りで AND。各キーワードは「チェック済みのいずれかの項目」に含まれていればよい |
| タイトル・チャンネル名 | `NFKC` 正規化 + 小文字化して比較（全角半角・英大小を吸収） |
| ひらがな/カタカナ | 統一して比較する（任意。実装する場合は `normalize()` 内で行う） |
| 動画ID | **大文字小文字を区別する**（YouTubeの動画IDは case-sensitive）。小文字化しない。前後の空白のみ除去 |
| URL貼り付け | 入力がYouTube URL（`watch?v=` / `youtu.be/` / `shorts/` / `embed/` 形式）に見える場合、動画IDを抽出して動画ID照合を行う。このとき動画IDのチェック状態に関わらず照合する |
| 空クエリ | 結果なし（全件表示にしない） |

### 1.4 結果表示

- 表示内容: タイトル、チャンネル名、動画ID（短縮表示）、所属ファイルのバッジ（likely / possible / unknown / excluded）、「N件目」
- 並び: 現在のファイルを先頭、次にファイル順（likely → possible → unknown → excluded）、ファイル内は元の順序
- 件数表示: 「全 123 件ヒット」のように総件数を表示
- 上限: 最初の50件のみ DOM 化し、「さらに表示」ボタンで50件ずつ追加。**全件を一度に DOM 化しない**
- 結果が0件のときは「該当なし」を表示
- クリック: `goTo(file, index)` を呼ぶ。移動後も検索パネルと結果リストは維持する（連続して別の候補を開けるようにする）

## 2. 設計上の重要事項

### 2.1 結果は「派生データ」にする（indexを保存しない）

分類のたびに元ファイルからレコードが消え、後続の index が繰り上がる。結果を保存すると古くなる。

- `state` に保存するのは**検索設定のみ**: `state.search = { query, fields, scope }`
- 結果リストは `state.data` から**そのつど導出**する。
- 各結果行のクリック先 `(file, index)` は導出時点の値を使う。分類・Undo の後は再導出して更新する。
- Undo で復元されるレコードは IndexedDB 由来の**別オブジェクト（コピー）**になる。オブジェクトの参照同一性に依存した設計にしないこと。

### 2.2 再描画で入力欄・埋め込みを壊さない

`render(root, state)` が画面全体を作り直す構造の場合、次の問題が起きる。
- 入力欄のフォーカスが外れ、入力が途切れる
- **YouTube埋め込みが再読込される**

対応:
- 検索パネルは全体 `render` に巻き込まず、**結果リスト部分のみを更新する専用関数**（例: `renderSearchResults()`）を用意する。
- 実コードの `render` の作りを確認し、検索パネルの入力欄が全体再描画で作り直されないようにする。難しい場合は、入力値・チェック状態・フォーカスを再描画前後で保存・復元する。
- 分類・Undo 後にパネルが開いて検索クエリがあるときは、結果リストのみを再導出して更新する。

### 2.3 日本語入力（IME）とデバウンス

- `compositionstart` ～ `compositionend` の間は検索を実行しない。`compositionend` 後に実行する。
- 通常入力は **250ms 程度のデバウンス**で検索する（ジャンプと違い埋め込み再読込は起こさないため、入力のたびの検索で問題ない）。
- Enter キーでデバウンスを待たず即時実行できるようにする。
- チェックボックスや検索範囲を切り替えたときは即時再検索する。

### 2.4 性能

履歴は数万件になりうる。

- レコードごとの**正規化済み検索用文字列を遅延生成してキャッシュ**する（`WeakMap<record, {title, channel}>` など）。毎回 NFKC 処理をしない。
- レコードが復元・差し替えされた場合に古いキャッシュを引かないよう、キャッシュキーはレコードオブジェクトにする。
- 線形走査で十分。インデックス構造は導入しない。
- 検索を実行するのは、検索パネルが表示されていて、クエリが空でないときだけ。分類のたびにバックグラウンドで常時検索しない。

### 2.5 安全性

- タイトル・チャンネル名は外部由来のデータである。結果表示には **`textContent` / `createElement` を使い、`innerHTML` に埋め込まない**。
- マッチ部分の強調表示をする場合は、文字列を分割して `<mark>` 要素を生成する。
- 検索処理は一切の書き込みを行わない。

## 4. 既存機能との競合チェックリスト

| 対象 | リスク | 対応 |
| :--- | :--- | :--- |
| ジャンプ（実装済み） | 移動処理の重複実装 | 結果クリックは `goTo` を再利用。UIは同一パネルにタブ統合 |
| ショートカット | 検索入力中の文字で分類が発動 | 既存のガードを検索欄・チェックボックスにも適用 |
| `state.busy`（Undo中） | 移動の競合 | `goTo` 側のガードに任せる。検索自体は読み取りのみなので busy 中も可 |
| 全体 `render` | 入力フォーカス喪失・埋め込み再読込 | 結果部分のみ更新（§2.2） |
| 分類・Undo 後の結果 | index が古くなる | 結果を派生データとして再導出（§2.1） |
| 書き込みキュー / 履歴 | なし（読み取り専用） | 触らない |
| `channel_labels.json` | 表示連携のみ | 書き込まない |
| 別ファイルへの `goTo` | 画面更新が不完全な恐れ | 必ずテスト。不備は `goTo` 側で修正 |

## 5. 禁止事項

- `writeQueue` / `history.js` / `file-system.js` / `jsonl-store.js` / `channel-labels.js` を変更しない。
- JSONLの元データ構造・プロパティに触れない。
- 検索結果に `index` を永続化・キャッシュして使い回さない。
- タイトル等を `innerHTML` に埋め込まない。
- 動画IDを小文字化して比較しない。
- 数値のみ入力を「ジャンプ」と自動判定する等、ジャンプと検索の入力を自動切替しない。
- 検索結果からの一括分類などの書き込みを伴う機能を追加しない（別タスク）。
- 外部ライブラリ・CDN を追加しない（完全ローカル完結の設計思想に反する）。
