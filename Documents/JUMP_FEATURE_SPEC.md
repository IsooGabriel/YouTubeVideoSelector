# ジャンプ機能 実装仕様書（AIエージェント向け）

対象プロジェクト: YouTube Video Selector（`PROJECT_FLOW.md` 参照）
目的: 現在表示中のファイル内で、指定した「N件目」のレコードへ直接移動する機能を追加する。

---

## 0. エージェントへの前提指示（最初に必ず読むこと）

   `state.file` / `state.index` / `state.busy` / `state.data` / `applyMoveInMemory` / `actions` / `render` / `notify` などの名前は仮定である。
2. 実装前に `src/main.js` と `src/ui.js` を読み、実際の名前・構造・`state.index` の終端状態の扱いを確認すること。仕様と実コードが食い違う場合は**実コードに合わせ**、差分を最終報告に書くこと。
3. 本機能は将来の「検索機能」（動画ID / タイトル / チャンネル名、チェックボックスで絞り込み）と連携する。検索機能は**今回は実装しない**が、§6 の拡張点を壊さないこと。

## 1. 要件

| 項目 | 内容 |
| :--- | :--- |
| 機能名 | ジャンプ（位置移動） |
| 動作 | 数値を入力して確定すると、`state.file` 内の N 件目へ移動して再描画する |
| 対象範囲 | 現在表示中のファイル内のみ（ファイル横断は今回スコープ外。ただし内部関数は対応させる） |
| ファイルI/O | **一切行わない**（メモリ上の `state` 変更と再描画のみ） |

### 1.1 仕様上の決定事項

- **「行」ではなく「N件目」と呼ぶ。** `jsonl-store.js` は空行をスキップするため、物理行番号と配列位置は一致しない場合がある。`JsonlError` の行番号（物理行）との混同を避ける。
- UI は **1始まり**、内部 `state.index` は **0始まり**。変換は `index = N - 1`。
- 番号は固定IDではない。分類のたびに後続が繰り上がるため、ジャンプは「現在の並びに対する一時的な位置指定」とする。
- 範囲外入力は**自動補正しない**。通知を出して移動しない（誤入力で意図しない位置へ飛ばないため）。
- 確定は「移動ボタン」または「Enterキー」のみ。`input` イベントごとの移動は**禁止**（YouTube埋め込みの再読込連発を避ける）。

## 2. 実装タスク

### Task 1: `src/main.js` — `goTo` の追加

位置を変更する**唯一の入口**として `goTo(fileName, index)` を実装する。

```js
// 擬似コード（実コードの命名に合わせること）
function goTo(fileName, index) {
  if (state.busy) return notify('処理中のため移動できません');

  const list = state.data[fileName];
  if (!list || list.length === 0) return notify('このファイルにはレコードがありません');

  if (!Number.isInteger(index) || index < 0 || index >= list.length) {
    return notify(`1〜${list.length} の範囲で指定してください`);
  }

  state.file = fileName;
  state.index = index;
  render(root, state);
}

actions.jump = (n) => goTo(state.file, n - 1); // n は UI の 1始まりの数値
```

要件:
- `state.busy` が true の間は拒否する（Undo実行中の位置ズレ防止）。
- `writeQueue` / `enqueueWrite` / `history.js` / `addHistory` には**触れない**。
- 入力値が `NaN`・小数・空・負数の場合も `Number.isInteger` で弾く。
- `actions.jump` に渡る前の文字列→数値変換は UI 側で行い、変換不能なら `NaN` を渡して `goTo` のチェックに任せる。

### Task 2: 既存の位置変更処理を `goTo` または同等の範囲チェックに寄せる

以下の箇所で `state.index` を直接変更している場合、範囲チェックを揃える。

- Undo 後の `state.index` 復元（復元位置が現在の `length` を超えうる → `0〜length` に丸める）
- 同一ファイル移動時の `state.index + 1`（**リスト末尾を超える現行挙動は維持**すること。挙動変更はしない）
- 分類後の `index` 更新

注意: 「最後のレコードを分類した直後に `index >= length` となる終端状態」が現行仕様に存在する可能性がある。存在する場合、`goTo` の範囲チェック（`index < length`）と矛盾しないよう、**終端状態は `goTo` 経由にせず現行処理のまま残す**こと。無理に統一して挙動を壊さない。

### Task 3: `src/ui.js` — ジャンプUI

- 配置: 現在の曲情報の近く。将来の検索UIと同じ「ナビゲーションパネル」にまとめられる構造にしておく（§6）。
- 要素:
  - 現在位置の表示: `12 / 340 件`
  - 数値入力: `type="number"`, `inputmode="numeric"`, `min="1"`, `max="{現在のファイルの件数}"`
  - 「移動」ボタン
- 任意（余裕があれば）: 「先頭」「末尾」「−10」「+10」ボタン。いずれも `goTo` を呼ぶだけで実装する。
- `length === 0` または終端状態では入力とボタンを `disabled` にし、例外を出さない。
- Enter キーで確定。`input` / `change` イベントでは移動しない。
- Android 操作を考慮し、ボタンは十分なタップ領域を確保する。
- 既存のDOM構築・イベント配線のスタイル（`render` の仕組み、イベントの渡し方）に**合わせる**。新しいパターンを持ち込まない。

### Task 4: キーボードショートカットのガード

分類用ショートカットが存在する場合、`event.target` が `input` / `textarea` / `select` / `[contenteditable]` のときはショートカットを無視する。

- 実装は**共通ヘルパー**として切り出す（例: `isTypingTarget(event)`）。検索機能の入力欄でも同じものを使う。
- 既にガードがある場合は、ジャンプ入力欄が対象に含まれることを確認するだけでよい。

## 3. 既存機能との競合チェックリスト

| 対象 | リスク | 対応 |
| :--- | :--- | :--- |
| `state.busy`（Undo中） | 位置が変わり復元位置とずれる | `goTo` で拒否 |
| Undo の復元位置 | 履歴が古い index を持ち範囲外になる | Undo側でも丸める |
| 終端状態（`index >= length`） | ジャンプUIが例外を出す | UIを disabled、`goTo` は範囲外を拒否 |
| 同一ファイル移動のスキップ | 位置変更ロジックが分散 | 範囲チェックを揃える（挙動は維持） |
| ショートカット | 数値入力中に分類が発動 | Task 4 のガード |
| 書き込みキュー / history | なし（I/Oなし） | 触らない |

## 6. 将来の検索機能との連携（今回は設計のみ考慮）

検索機能は別タスクで実装する。今回の実装で以下を満たしておくこと。

1. **`goTo(fileName, index)` はファイル名を引数に取る。** 検索結果のクリックで4ファイル横断の移動に再利用する。
2. **UIはナビゲーションパネル内に収める。** 将来、同パネルに「ジャンプ / 検索」のタブまたはモード切替を追加できる構造にする。
3. **ショートカットのガードと `notify` は共通ヘルパー化する。**
4. 検索側の方針（参考・今回は実装しない）:
   - 検索対象: 動画ID / タイトル / チャンネル名。チェックボックスで複数選択して絞り込む。
   - 検索結果は **index ではなくレコードの同一性（動画ID or ハッシュ指紋）で保持**する。分類のたびに index が繰り上がるため。
   - 結果クリック時に現在位置を引き直してから `goTo` を呼ぶ。見つからない場合（別ファイルへ移動済みなど）は再検索を促す。
