# データ契約とパターン台帳

この文書は履歴データの扱いを定める。実データそのものや個人情報は載せない。確認日は 2026-11-04。

## 対象ファイル

| 分類 | ファイル |
| --- | --- |
| 可能性が高い | `likely.jsonl` |
| 可能性あり | `possible.jsonl` |
| 判断保留 | `unknown.jsonl` |
| 対象外 | `excluded.jsonl` |

1行につき1つのJSONオブジェクトを格納する。分類はレコード内ではなく所属ファイルで表す。`channel_labels.json` はチャンネル単位の補助データであり、動画レコードを変更しない。

## 保護する条件

- 読込・書出・再読込で、全レコードの値、未知フィールド、順序を保持する。
- バイト差があれば種類（キー順、空白、Unicode、改行、末尾改行、BOM）を測定し、依頼者の判断を得る。
- 4ファイル合計の件数は分類移動の前後で変えない。
- `video_id` のファイル内・ファイル間重複を検出する。
- JSONとして不正な行があれば、書込みを中断する。

## フィールド

現行コードで表示・検索・ソートに使う代表フィールドは次である。その他のフィールドは未知フィールドとしてそのまま保持する。

| フィールド | 想定型 | 用途 |
| --- | --- | --- |
| `video_id` | 文字列 | 同一性・検索 |
| `url` | 文字列 | 動画リンク |
| `title_clean`, `title_raw`, `title` | 文字列 | タイトル表示・検索・ソート |
| `channel`, `channel_url` | 文字列 | チャンネル表示・検索・ソート |
| `signals`, `warnings` | 配列 | 既存の判定情報 |
| `play_count` | 数値 | 表示・ソート |
| `first_played`, `last_played` | 日時文字列 | 表示・ソート |
| `artist_guess` | 文字列またはnull | ソート |
| `plays`, `ad_plays` | 配列など | 保持のみ（大きいため表示用モデルへ複製しない） |

## パターン台帳

以下はマスター命令書に記載された、`likely.jsonl` 661件の確認結果である。他の3ファイルと16万件規模の実データは未調査。

| ID | 内容 | 件数 | 扱い | 対応テスト |
| --- | --- | ---: | --- | --- |
| P-001 | 日時にミリ秒がない形式が混在 | 7 | 文字列比較せず日時として比較 | Phase 1で追加 |
| P-002 | タイトル・チャンネルが空で削除/非公開を示す警告 | 5 | ソートは末尾、検索で例外にしない | Phase 1で追加 |
| P-003 | `artist_guess` がnull | 225 | ソートは末尾 | 既存ソートテストの一部 |
| P-004 | 同名で異なるチャンネルURL | 2名 | 名前の次にURLで比較 | 既存ソートテストの一部 |
| P-005 | タイトル先頭が記号・絵文字 | 約70 | ソート用文字列では先頭記号を除く | 既存ソートテストの一部 |

## Phase 0で未確認の項目

`tools/inspect-data.js` を実データの**コピー**に実行し、件数・形式だけを確認する。

- 4ファイル間を含む `video_id` の重複
- BOM、改行形式、末尾改行、空行、極端に長い行
- フィールド集合、型、空値、日付形式
- `title_clean` と `title_raw` の差
- 分類ファイル固有の形式
